# 프론트 남은 문제

`feat/new-screens-design` 기준. 지금 화면은 전부 예시 데이터(`src/mocks/data.js`)로 동작하고, 필드명은 API 명세 v1.4에 맞춰 두었다.

## 백엔드 연결 때 할 일
- [ ] 상황 변경: `POST /users/me/life-stage-change` 응답의 새 로드맵으로 교체한다. 지금은 화면에서 진행상태만 초기화한다 (`resetRoadmap`). 내 로드맵의 상황 바꾸기 모달과 맞춤 설정 화면 둘 다 해당한다.
- [ ] 온보딩 완료: `PUT /users/me/profile` 연결. 응답의 로드맵으로 교체한다.
- [ ] 첫 취업으로 변경 시 `suggestReview`가 true면 합격 후기 작성을 제안한다. 아직 만들지 않았다.
- [ ] 로드맵 진행률: 임시 가중치 계산(`summarize`) 대신 서버의 `progress`를 쓴다.
- [ ] 기준일 `BASE_DATE`(2026-10-25)를 오늘 날짜로 바꾼다.

## 아직 없는 화면·입력
- [ ] 내 기록 `/me`: 제목만 있다. 상황을 바꾸면 "활동 기록으로 남아요"라고 안내하는데 볼 곳이 없다. `GET /roadmaps/me/history`, `GET /users/me/posts` 연결 필요. 만들면 사용자 메뉴에 넣는다.
- [ ] 채용공고 상세 `/jobs/:jobId`, 게시글 상세 `/community/:postId`: 제목만 있다.
- [ ] 회원가입: 비밀번호 규칙(8~20자, 영문·숫자·특수문자 포함)과 약관 동의(`agreeTerms`, `agreePrivacy`) 입력이 없다.

## 명세 확인이 필요한 것
- [ ] 닉네임 수정 API가 없다. 그래서 맞춤 설정에서 읽기 전용이다.
- [ ] 거주 지역, 진로 목표가 시안에는 있지만 API와 ERD에 없다. 그래서 거주 지역은 희망 지역(`jobPreference.regions`)으로 대체하고 진로 목표는 뺐다.
- [ ] 알림 `link.targetType` 중 `POST_LIST`, `CALENDAR`는 명세 예시에 없어 임시로 정한 값이다 (`src/utils/notification.js`).
- [ ] 캘린더 일정에 장소 필드가 없다. 지금은 운영기관을 대신 보여 준다.

## 팀에서 정할 것
- [ ] 상단 메뉴: 시안은 홈·내 로드맵·지원정보 3개이고, 제안서 §5-5는 내 로드맵·맞춤 채용·커뮤니티·NEXT 캘린더 4개다. 시안대로 하면 채용·커뮤니티·캘린더로 가는 메뉴가 없어져서 제안서 4개를 유지했다. 홈은 로고, 지원정보는 홈의 링크로 들어간다.
- [ ] 메인 색: 흰 글자 대비를 맞추려고 `#009689`를 `#00857A`로 조정했다. Figma에도 반영할지 정한다.
- [ ] 맞춤 채용 공고의 공식 사이트 링크는 예시로 고용24 첫 화면을 가리킨다. 실데이터 연결 시 공고 원문 주소로 바뀐다.
